The GhostGet claims register

This page lists every claim GhostGet's maintainer rules make about the product and says whether an automated check covers it. Each entry gives one claim, its status, the kind of check behind it, the conditions it assumes, and what that check leaves out. The build generates the page from the register in GhostGet's repository, so the counts match the current release.

Latest release: {{GHOSTGET_RELEASE}}. For a guided read of the claims that matter most when an agent writes on your behalf, see the post What GhostGet has and has not verified.

How to read a claim

A claim is evidenced when its layer runs in CI, planned when the verification plan schedules its layer, and not verified when no automated check covers it. Evidenced does not mean proved. It means a named check runs on every change and passes.

Each entry also carries its own not-verified scope: the part of the claim the check does not cover. The repository's verify:claims check fails when the generated assurance document is stale, when a rule in a scanned maintainer guide has no current register entry, when a rule does not list exactly the claims that quote it, when an evidenced property claim names a test that runs no property, or when an evidence path no longer exists.
