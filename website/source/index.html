Ghostget

Let your agent read pages, save media, and use your accounts through named actions.

Ask your agent to install Ghostget. It can then read a page, save one media item, or use an account you connected, and each action returns only its result instead of a browser to click through. A measured article read comes back at about 3,800 tokens where the raw page carries 36,000, and the agent never sees your logins.

Smaller answers cost fewer tokens.

Your model provider charges for everything the agent reads, so a smaller answer is faster and cheaper. On September 22, 2026, ghostget read returned the bytes below for each URL versus the raw HTML the URL serves. Every row was a single HTTP capture with no browser process and capture_status: "complete".

At roughly four bytes per token, that Wikipedia read costs about 3,800 tokens where the raw page carries about 36,000. The table counts bytes because tokenizers differ.

Browser-driving agents pay a different curve because page state re-enters context on every step. A July 2026 comparison matrix cites Microsoft’s reported benchmark at about 114,000 tokens for a typical Playwright MCP task versus about 27,000 for its disk-first CLI. Treat any single figure as an estimate. Ghostget returns one result per call, so no page state comes back for the agent to re-read between steps.

Your agent never steers a browser.

Browser-using agents stream the live page into the model and let it choose each click. With Ghostget, the agent asks for an outcome, Ghostget runs one reviewed exchange with the service, and only the result comes back.

The agent has nowhere to navigate. Page state and screenshots never enter its context, it never sees a cookie or token, and there are no selectors for it to guess. If a service changes how it responds, the affected action becomes unavailable instead of improvising a click path.

Some pages need a real browser to render. For those, Ghostget runs its own browser internally, at most two at a time. The agent can request the page but can’t steer the browser. The agent-browser comparison shows how Ghostget uses the same kind of engine without handing it to the agent.

Each request has one named action

Your agent requests a supported action, such as reading an inbox or saving a video. Ghostget checks the inputs and account, makes the request, and returns a structured result. Sign-in details stay inside Ghostget.

  1. 01
    Name the job

    The agent asks for an outcome, such as reading an inbox or preserving one video.

  2. 02
    Match one action

    Ghostget resolves one installed, supported action. There is no general browser or request tool to fall back on.

  3. 03
    Check the account

    Ghostget checks the exact service, account, and risk level before anything runs.

  4. 04
    Run one exchange

    Your sign-in stays locked inside Ghostget and can reach only the service that action needs.

  5. 05
    Return the result

    Your agent gets a structured result, a note of anything incomplete, or a saved record that the outcome is not yet known.

Keep accounts and saved work under your control.

Account state and saved results stay on your machine. Requested work contacts the source service, and your agent can receive the results you give it.

Your sign-ins stay here
Ghostget stores sign-ins on this machine, including any linked-device store you choose to use. Your agent gets a named action and its result, never cookies, tokens, or a browser it can steer.
Import a token without showing it
For X, ghostget vault import-x accepts a 1Password field reference instead of a pasted secret; Ghostget verifies the X user and stores the token privately on your machine. It is a token importer for one provider, not a general password manager.
Only the traffic you asked for
Reads and actions contact their selected sources. Provider sign-in and explicitly started messaging sync also use the network. The CLI and SDK send no website analytics.
Reads you can open later
Provider-read snapshots are encrypted on your machine; owner messaging keeps a separate private local history and journal. A failed refresh does not erase the last verified state.
Writes need your go-ahead
Anything that changes an account needs a preview and your approval: a one-time confirmation, or a limited grant you set up for owner messaging. If a write went out and its result is unknown, Ghostget won’t send it again. It stays marked unsettled until separate evidence shows what happened.
When a service changes
If a service changes how it responds, the affected action stays off until it is reviewed again. Ghostget never quietly falls back to a browser.
Bring your own agent
Ghostget supplies the local tools and a macOS menu-bar companion for outputs and CLI guidance. Your agent owns the model and planning.

How Ghostget compares with browser tools.

Most “browser use” tools give the model a browser to drive, on your machine or in the cloud. With Ghostget, the agent asks for a reviewed outcome and gets back one result. Compare the approaches in detail.

Before you install.

How do I set it up?

Tell your agent: “Install Ghostget {{GHOSTGET_RELEASE}}, then use it to read https://example.com and summarize it.” Any agent that can run a terminal command can do the rest. Without an agent, install Bun and run the two commands in the install section above.

Which agents does it work with?

Any agent that can run commands: Claude Code, Codex, Cursor, Gemini CLI, or your own. The optional Agent Skill teaches it the Ghostget commands and their limits in one step.

Does Ghostget need an account?

No. Install the CLI and read a public page. You connect a service only when you want its actions, and each connection is stored on your machine. Hraness Accounts sign-in is optional and is not needed for page reads or provider setup.

Does it use my credentials?

It uses a sign-in you already have for a service, on this machine, and keeps it out of your agent’s hands. The agent calls a named action and gets a typed result. Ghostget’s normal outputs do not include cookies or tokens. The calling agent keeps the separate tools and permissions you give it.

What does it cost?

Nothing. Ghostget is free and MIT licensed, with no hosted tier and no paid plan. You pay your model provider and any service subscriptions you already have.

Does it phone home?

No. The CLI and SDK send no analytics to ghostget.com; they make only the network requests the action you chose requires. This website counts page views with cookieless analytics and honors Do Not Track. The privacy page explains both.

Which platforms does it run on?

macOS and Linux with Bun 1.3.14. Actions that read iMessage or Apple Photos need macOS. Beeper actions need Beeper Desktop on the same machine, and WhatsApp reads need a linked device.

Is Ghostget an AI agent?

No. Ghostget supplies a CLI, an SDK, and a macOS menu-bar companion. Your agent brings the model and the plan; Ghostget manages account permissions, approvals, and the records of its actions.

How is this different from browser-use or Browserbase?

Those tools give the model a browser to drive, locally or in the cloud, and the model reads page state and chooses each step. With Ghostget, the agent asks for a named, reviewed action and gets back one result, so it can only do what is on the published action list. The comparison page covers each tool in detail.

Does Ghostget use a browser internally?

Yes, in two cases. When a page can’t be read without rendering it, Ghostget runs its own browser, at most two at once; page reads try a single HTTP request first. Some signed-in provider actions, such as certain LinkedIn and Instagram reads, also run inside a contained browser session. In both cases the browser accepts no selectors, coordinates, or scripts from the caller.

Where do tokens and credentials live?

On your machine, in a locked local store the agent cannot read. Each sign-in is bound to one account and one service, and secrets resolve inside an isolated credential helper. For X specifically, ghostget vault import-x can import an OAuth token by 1Password field reference so the token is never pasted or typed into an agent’s context.

Does it bypass login, paywalls, access controls, or DRM?

No. Media archiving is limited to one item you are authorized to access that is finite and not protected by DRM. Ghostget does not bypass payment, authentication, access controls, or DRM.

What happens when a service changes?

The affected action becomes unavailable until its definition is updated, reviewed, and tested. Ghostget never quietly falls back to a browser, so a changed page never turns into a guessed action.

Why does Ghostget refuse to retry some writes?

If a request left the machine and its response was lost, the effect may already exist. Ghostget keeps that uncertainty visible and reconciles it from separately obtained evidence instead of sending the request again.

What does release {{GHOSTGET_RELEASE}} include?

Page capture, media archives, encrypted reads, and {{PROVIDER_CALLABLE_ACTION_COUNT}} supported actions across {{PROVIDER_SURFACE_COUNT}} services. ghostget capabilities is the source of truth for what is installed and available on your machine, and the provider list names every action in this release.
