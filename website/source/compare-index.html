Six ways agents reach the web, and where Ghostget fits

“Browser use for agents” names four of the six approaches below: agent libraries that drive the browser for you, tool servers that give your agent browser controls, browser CLIs that let it steer from the shell, and hosted browsers you rent by the session. The fifth skips your browser entirely: reader services fetch the URL and return Markdown. A sixth skips web pages: integration platforms call app APIs with sign-ins they manage. Ghostget offers named, reviewed actions that each return one result, and the agent never gets a browser to steer.

This page describes each project as published in September 2026, with Crawl4AI, Composio, Arcade, and Pipedream Connect checked on 28 September 2026, and Ghostget {{GHOSTGET_RELEASE}}. Linked pages cover one tool each in more detail.

Agent libraries drive the browser for you

browser-use, Stagehand, and Skyvern own the whole job. You hand them a goal in plain language, and the model loops: observe the page through a DOM serialization or screenshot, plan the next step, act through CDP or Playwright, and repeat until the goal is done. This is the right shape for open-ended multi-step work. The cost profile is the loop itself: every step re-reads the page, so context grows with task length, and the model decides each click inside a surface you cannot enumerate in advance.

Ghostget vs browser-use covers the detailed boundary difference.

Tool servers give your agent browser controls

Playwright MCP and chrome-devtools-mcp keep the agent you already run in charge and expose browser actions as MCP tools. Your agent calls browser_click or browser_snapshot; the page's accessibility tree streams back into its context after each call. Microsoft's own reported benchmark puts a typical Playwright MCP task near 114,000 tokens against about 27,000 for its disk-first CLI sibling, so this approach pays for flexibility in context size. Your harness's permission prompts are the guardrail; the page decides what the agent sees next.

Ghostget vs Playwright MCP covers the token and authority trade in detail.

Browser CLIs put steering in the shell

agent-browser and the Playwright CLI turn browser control into commands an agent composes: open, click, type, snapshot, eval. The token cost is lower than streamed page state because snapshots land on disk or stdout when asked. The authority question stays open: the agent chooses selectors, coordinates, and JavaScript, so every page it reaches is a place it can act.

Ghostget itself pins agent-browser 0.32.3 as an internal dependency for page captures that need rendering. The agent never reaches it: Ghostget caps how many of those browsers run at once, and no Ghostget interface accepts a selector, coordinate, or script. Ghostget vs agent-browser explains how Ghostget uses the same engine without handing it to the agent.

Hosted browsers you rent by the session

Browserbase, Steel, and Hyperbrowser sell managed cloud sessions: parallel Chromium with proxies, stealth, replay, and compliance tiers that the three approaches above can run on. They answer where the browser runs and at what scale, not what the agent is allowed to do once it is inside one.

Ghostget vs Browserbase covers when hosted sessions are the right tool and when local named operations replace the session entirely.

Reader services fetch the URL for you

Firecrawl and Jina AI Reader remove the steering entirely: you hand them a URL, their servers fetch and render it, and clean Markdown or structured data comes back. Firecrawl grows that one call into a pipeline with crawl, map, search, interact, and agent endpoints, billed in per-page credits. Jina Reader keeps it to a prefix, r.jina.ai, rate-limited without a key and billed by output tokens with one. Neither leaves a file on your machine by default. Crawl4AI is the open-source option you run yourself: a Python crawler on Playwright, built for whole-site crawls and RAG pipelines.

Ghostget vs Firecrawl and Ghostget vs Jina Reader compare hosted fetching with a local read that saves Markdown into a searchable vault.

Integration platforms act in your apps

Composio, Arcade, and Pipedream Connect skip the browser and call app APIs. They offer large integration catalogs with managed sign-in, built for products whose agents act for many users. Ghostget covers far fewer services, keeps each sign-in on your machine for one person’s agent, and shows a preview before each write.

Where Ghostget fits

Ghostget does not give the agent a browser at any layer. The agent requests a reviewed outcome such as messaging.list or a page read; the kernel binds the exact account, transport, contract version, and risk level; one exchange runs; one structured result comes back. The agent has nowhere to navigate, no selector to guess, and no cookie it can copy out. When a service changes shape, the action stays unavailable until it is reviewed again instead of improvising a new path.

This trades reach for certainty: anything not in the supported action set is unavailable, by design. Public-page reads need no account; a measured article read returns about a tenth of the raw page's bytes, and the homepage shows the numbers.

Choose the approach before the tool

If the job is open-ended, a browser-driving agent earns its context cost. If the job recurs, the fixed contract wins: a named operation is cheaper in tokens, safer in blast radius, and reviewable in a way a thousand improvised clicks are not. An agent setup can use both: a browser driver for one-off work, and fixed actions for the paths that must be right every time.

Ghostget supplies those fixed actions. It publishes no hosted browser, reader service, MCP server, or agent loop; it supplies the local operations your agent calls from whatever harness you already use.
